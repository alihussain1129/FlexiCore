# FlexiCore implementation progress

Last updated: 2026-10-20. This file records what was actually run and observed.
Anything not listed under "Verified" must be treated as unverified.

## Product requirements (summary)

- Two independent, offline-first ERP apps: FlexiCore Desktop (Windows) and
  FlexiCore Mobile (Android), each with its own local database and no mandatory
  server, cloud or internet connection for ordinary use.
- Local authentication and authorization enforced in the app/data layer.
- Offline license verification must remain effective.
- Optional Settings -> Linked Devices pairing and, later, a deliberate sync
  protocol. Sync is never a prerequisite for local use.
- Modules, built incrementally: dashboard/setup, organizations/users/roles,
  catalog, inventory, customers/suppliers, sales/POS, purchases, accounting and
  reports, customization/permissions/audit, settings/backup/licensing/linking.

## Decisions

- **Database:** SQLite through drift. Resolved versions: drift 2.35.2,
  drift_dev 2.35.1, path_provider 2.1.6, sqlite3 3.5.2 (transitive).
- **No `sqlite3_flutter_libs`.** drift 2.32+ bundles sqlite3 through the
  sqlite3 3.x package; the old helper package is end-of-life.
- **Money** is stored as integer ten-thousandths (`*_e4`) to match the server's
  `numeric(18,4)` without floating point.
- **Schema** mirrors server migration 0012: soft delete (`deleted_at`),
  `version`, `updated_at`, `origin_device_id`, partial unique indexes on active
  rows for unit code and product SKU.
- **Validation** patterns and limits are copied from the CHECK constraints in
  `0012_catalog.sql`. `CatalogRules.cs` on the server has NOT been compared.
- **Data location:** `getApplicationSupportDirectory()`, never temp/cache.
- Generated `app_database.g.dart` is intended to be committed (it is not
  gitignored) so a fresh checkout builds without running build_runner.

## NOT verified

  (the tests use a temp directory).
- Any user-facing workflow: nothing in the app uses the database yet.
- Offline operation of the app. The primary app still requires the API.
- Schema upgrade paths: only version 1 exists. A pre-migration backup of the
  database file is not implemented.
- Backup/restore, encryption at rest, local authentication, local licensing.
